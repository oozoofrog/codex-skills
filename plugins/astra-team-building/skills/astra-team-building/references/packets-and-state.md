# 배정·반환·상태

짧고 자기완결적인 배정을 사용한다. 모든 항목을 고정 양식으로 채우거나 긴 대화를 복제할 필요는 없다. 작업 방법은 담당 세션이 선택하되 정확성·권한·호환성에 필요한 계약은 생략하지 않는다.

## 배정할 정보

- 원 목표에서 맡은 산출물과 관측 가능한 완료 조건, 선행 입력과 미정 계약
- 역할, 선택 모델·effort와 이유, 실제 절대 작업 경로·수정 범위·owner
- 관련 사용자 지시·AGENTS.md·필요한 도메인 지침, 보존할 기존 변경, 기존 권한
- 필요한 원문 오류·재현·파일·로그 위치, 공유 자원과 검증 환경
- 범위 밖 결정·환경 차단·새로운 설계 필요를 리더에게 반환할 조건

예를 들어 파서 구현에는 입력/오류 계약과 테스트 입력, 승인된 파일, 실제 worktree를 준다. 탐색에는 조사할 질문과 반환할 근거 위치를 준다. 독립 리뷰에는 원 요구와 고정된 실제 산출물을 주고 구현자의 성공 결론은 주지 않는다. 모든 역할에 저장소 전체 문서를 사전 읽기로 부과하지 않는다.

Git 변경 과제에는 repository/common-dir, branch·기준/목적지 HEAD, staged/unstaged/untracked 보존 대상과 commit/push 권한을 추가한다. 단순 조사 packet에는 불필요한 변경 권한을 넣지 않는다. 추가 위임은 리더에게 제안하도록 한다.

## 반환할 증거

자기 범위의 완료/부분 완료/차단, 실제 변경 경로·diff 또는 산출물, 실행한 검증과 결과·로그 위치, 미실행 검증과 이유, 필요한 결정·남은 문제를 반환한다. 명령 예시와 실제 실행을 구별한다. 지원 도구에서 관측할 수 없는 모델·effort·사용량은 `unverified`/`null`로 둔다.

리더는 받은 결과를 확인하되 완료된 일을 무조건 재수행하지 않는다. 소스·정적 검사, build/test, Simulator, 실기기·사용자 경험, 설치·릴리스·외부 전송은 각각의 증거로 보고한다. worker의 완료 메시지만으로 전체 완료를 선언하지 않는다.

## 장기 작업의 상태

기존 `.codex/work/<task-id>.md` 또는 현재 작업에서 쓰는 복구 문서가 있으면 그곳을 단일 전체 복구 지점으로 유지한다. 없다면 장기 과제에만 task별 문서를 만든다. 다른 task의 state를 덮어쓰지 않는다. `session-continuity`가 이미 적용됐다면 그 기존 구조에 간결하게 추가하며 다른 스킬 설치나 초기화를 자동 실행하지 않는다.

이어갈 만큼 다음을 기록한다.

- 목표·완료 조건·현재 제약·사용자 지정과 남은 결정
- 세션 ID, 역할·범위·모델/effort 요청과 관측, 마지막 실제 상태
- 경로·branch·HEAD와 dirty 입력, writer/공유 자원 owner, 의존 관계
- 산출물·검증 근거·미확인, 다음 행동과 재배정 이유

원문 로그·비밀·인증·전체 대화는 state에 복사하지 않는다. 스킬 이름이나 상태 문서가 새 권한을 만들지 않는다. 이전 `astra-orchestrator` 작업 state가 있으면 참고할 사용자 데이터로 보존하고 새 정책을 적용하는 요청 범위에서 현재 사실과 대조한다. 이름 변경만으로 과거 state를 삭제·일괄 마이그레이션하지 않는다.

재개 시 worker ID의 생존, cwd/worktree, 실제 변경, 가용 슬롯·설정을 확인한다. 과거 `running`/`done`을 현재 상태로 간주하지 않는다. 접근 불가 세션은 `unknown`으로 두며 쓰기 충돌 가능성을 해소한 후 재배정한다.
