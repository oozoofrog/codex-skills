# 평가와 배정 개선

최적화는 품질을 충족하는 결과를 얻는 비용을 줄이는 과정이다. 이 스킬의 역할표가 실제 프로젝트에서 최적이라고 가정하지 않는다. 평소에는 요청된 일을 한 번 완료하면서 얻는 증거로 조정한다. 비용 비교를 위해 같은 제품 작업을 자동으로 여러 번 수행하지 않는다.

## 실제 작업에서 볼 신호

| 관측 | 다음 배정에서 검토할 조정 |
| --- | --- |
| 구현은 빠르지만 전달·검토·병합이 적체 | 역할 합치기, 동시 배정 줄이기, 계약 개선 |
| 리더가 바쁘고 독립된 확정 과제가 대기 | 자원·예산이 허용하면 구현/검증 역할 추가 |
| 반복 재작업·가정 누락 | 입력 계약과 증거 보강, 필요한 모델/effort 상향 |
| 인증·기기·공유 cache 대기 | 환경·점유 조정. 모델 증설로 해결하지 않음 |
| 좁은 반복 작업이 충분한 증거로 안정 | 다음 과제에서 더 가벼운 배정 검토 |

전체 완료까지 걸린 시간, 관측 가능한 총 사용량, 전달·리뷰·재작업 부담, blocking finding과 완료 증거를 기록한다. 리더·모든 worker·재시도·통합·검증을 포함한다. 가격을 확인하지 않았다면 토큰을 임의 금액으로 환산하지 않는다. 알 수 없는 비용·시간은 0으로 채우지 않는다.

## 선택적 비교 실험

사용자가 비교 평가를 요청했을 때만 같은 입력·완료 기준·시작 상태·환경에서 단독 수행과 필요한 팀 후보를 비교한다. 비교 목적상 필요한 후보만 실행한다. 별도 격리 workspace와 session을 사용하고 정책/스킬 버전·리더 설정·요청/관측 설정을 기록한다. 실제 프로젝트 변경이나 사용자 데이터에 같은 실험을 중복 적용하지 않는다.

품질 기준 미달·미실행 검증·설정 불일치가 있는 실행을 성공한 절감 사례로 넣지 않는다. 실패·차단·재시도 비용도 누락하지 않는다. 적은 표본은 관측 결과로만 보고하며 다음 작업에 보편적인 최적값으로 고정하지 않는다.

## 행동 점검

스킬 수정 뒤에는 복잡도에 맞춰 독립된 평가 세션에 스킬과 현실적인 입력만 제공할 수 있다. 기대 답·수정 의도는 미리 주지 않는다. 파일 격리와 평가 side effect를 제한하고 판단을 실제 행동과 구분해 기록한다.

주요 사례는 작은 직렬 수정, 독립 모듈 구현, 고위험 read-only 계약 검토, 한 기기를 공유하는 검증, 명시 모델 미지원, writer 상태 불명, 모델 변경 후 인계, 검토 적체다. 스키마/문서/시나리오 검사, 시나리오에 대한 계획 응답, 실제 spawn/반환, 파일 변경/통합, 사용자 환경 결과는 서로 다른 증거다.
