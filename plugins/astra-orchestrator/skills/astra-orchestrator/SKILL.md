# Astra Orchestrator

현재 세션을 리더로 유지하며 사용자가 승인한 목표를 구현·검증·필요한 통합까지 완료한다. 사용자 지시는 이 스킬의 일반 규칙보다 우선하며, 상위 지침과 실제 도구 권한을 따른다. 역할 이름이나 스킬 호출은 commit·push·삭제 등 추가 권한을 만들지 않는다.

## 직접 수행과 위임

- 작은 작업, 짧은 조사·Git 조회, 선행 결과에 밀접하게 의존하는 작업은 리더가 직접 처리한다. 스킬 호출만으로 워커를 생성하지 않는다.
- 독립된 산출물과 완료 조건이 있고, 리더도 별도의 유용한 작업을 진행할 수 있으며, 병렬 실행의 이익이 전달·통합 비용보다 클 때 위임한다. 명시적으로 요청된 역할 분리나 독립 검토도 위임 근거다.
- 위임한 구현은 중복 수행하지 않는다. 일반 워커는 구현·테스트, 별도 Git Steward는 필요한 Git 변경·통합을 맡는다. 위임할 Git 변경·통합 과제가 있을 때 Steward를 생성하며 일반 워커와 합치지 않는다. 위임 이익이 없는 작은 Git 과제는 리더가 같은 안전 경계를 적용해 직접 처리한다.
- 한 worktree에는 한 시점에 한 writer만 둔다. 병렬 구현은 별도 worktree와 독립된 공유 자원을 사용하고, 격리할 수 없으면 직렬화한다.

## 모델 정책과 필요한 문서

기본 `astra-only`는 기존과 같이 모든 참여 세션에 `gpt-6-astra`를 사용한다. 리더 `xhigh`, 일반 워커 `high`, 기계적 워커 `medium`, 전문 작업 `xhigh`, 중요한 독립 최종 검토 `max`가 운영 기본값이다. 실행 중 리더의 설정을 변경하지 않는다. 사용자의 명시적 모델·추론 선택은 해당 범위에 우선하며, 예외는 Astra-only 실행과 구별해 보고한다.

사용자가 **혼합 모델 / mixed-model**을 명시한 작업만 [혼합 모델 정책](references/model-routing.md)을 읽고 적용한다. 그 정책이 위임 대상의 모델 선택을 담당하며, 기존 역할·Git·검증 규칙은 그대로 적용한다. `astra-only`와 `mixed-model`은 이 스킬의 정책 이름이지 Codex 설정 키나 새 CLI 옵션이 아니다. “비용을 줄여 달라”, 스킬 설치·편집 또는 문서 안의 예제만으로 혼합 정책을 활성화하지 않는다.

- 세션 생성·후속 배정 경로를 선택할 때 [세션 도구](references/session-tools.md)에서 실제 설정 우선순위·Standard 속도·관측 한계를 확인한다. 모델·effort를 실제 도구 인자로 지정하되 custom agent의 덮어쓰기도 확인한다.
- 역할 선택, 실패 재평가, 독립 검토는 [역할과 검토](references/roles.md)를 읽는다. 해당 문서의 Astra effort 기본값은 Astra 역할에 적용하며 다른 모델에 그대로 복사하지 않는다.
- 업무 전달에는 [전달할 정보와 반환 증거](references/packets.md)를 참고한다. 필요한 맥락만 제공하고 수행 절차는 워커가 선택한다.
- Git 변경에는 [Git Steward 안전 경계](references/git-steward.md)를 적용한다.
- 장기 작업에 session-continuity를 함께 쓰거나 기존 task state가 있으면 [작업 인계](references/orchestration-handoff.md)를 읽는다.
- 설치·수동 시작 안내가 필요할 때만 [README](README.md)를 읽는다.

## 완료 조건

목표·변경 범위·기존 권한·관측 가능한 완료 조건을 현재 맥락에서 확인한다. 이미 확인한 문서를 다시 읽거나 기존 권한을 다시 묻지 않는다. 필수 정보나 권한이 부족한 행동만 보류하고 독립적으로 가능한 작업은 계속한다.

리더는 실제 변경과 결과를 완료 조건에 대조한다. 변경에 필요한 검증을 실행하고 발견된 관련 실패를 해결한다. 통과한 검증은 관련 입력 변경·실패·새 근거가 있을 때만 반복한다. 독립 검토가 필요한 결과는 검토를 통과하고 blocking finding이 없어야 완료다. Git 통합 성공이나 워커의 완료 메시지만으로 제품 완료를 선언하지 않는다.

최종 보고에는 변경 파일, 검증 결과, 남은 제한을 포함한다. 미실행 필수 검증은 미완료/미확인으로 명시하며 코드·자동화/Simulator·실기기/사람·설치/릴리스/외부 전송의 증거를 구별한다. 장기 작업만 `work/astra-orchestrator/STATE.md`에 목표, 담당 세션·범위·의존성, 권한, 증거, 남은 작업을 이어갈 만큼 기록한다. 기존 `.codex/work/<task-id>.md`를 함께 쓰면 전체 목표·완료 상태를 중복 관리하지 않고 해당 state를 참조한다.
