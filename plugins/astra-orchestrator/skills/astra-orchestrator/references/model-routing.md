# 선택형 혼합 모델 정책

`mixed-model`을 사용자가 명시적으로 선택한 작업에만 적용한다. 선택은 해당 작업 범위이며 새 목표나 새 세션에 자동 전파하지 않는다. 재개할 때는 원래 사용자 요청과 현재 지시를 확인한다. state의 정책명은 권한을 새로 만들지 않는다.

## 배정 순서

먼저 위임 자체의 이익을 판단한다. 짧은 독립 작업도 전달·통합 비용이 더 크면 리더가 직접 한다. 위임이 필요할 때만 다음 후보를 현재 클라이언트의 가용 조합에서 고른다. 이 표는 운영 출발점이며 성능이나 절감률을 보장하지 않는다.

| 과제 | 시작 후보 | 반환 기준 |
| --- | --- | --- |
| 위치·심볼 탐색, 명확한 로그/자료 추출, 독립적으로 확인 가능한 좁은 조사 | `gpt-6-luna` / `high`, 읽기 전용 권한 | 파일·심볼·근거 위치, 누락·불확실성 |
| 사양과 허용 변경 범위가 확정된 구현·회귀 테스트 | `gpt-6-sol` / `medium` | 실제 diff, 실행한 검증, 미검증 |
| 요구사항 해석·아키텍처·동시성·소유권 계약·복구 불가능한 영향 판단 | 리더 직접 또는 필요한 Astra 전문 역할 | 근거와 반례, 검증 범위 |
| Git 변경·통합 또는 중요한 독립 최종 검토 | 기존 Astra 역할/effort | 기존 Git Steward·reviewer 계약 |

읽기 전용이라는 이유만으로 Luna에 맡기지 않는다. 예를 들어 소유권 계약의 타당성 검토는 코드 위치 추출과 다르다. 분류에는 모호성, 상호 의존성, 실패 영향, 검증 가능성, 필요한 맥락을 함께 사용한다. Sol의 범위가 확정되지 않았다면 먼저 리더가 결정한다. 혼합 정책이어도 실제 하위 모델을 쓰지 않은 실행은 혼합 모델 절감의 근거가 아니다.

## 실행 전 확인

사용자의 모델·effort·속도·비용 제한은 개별 필드별로 보존한다. 미지정 필드만 선택한다. 명시 조합이 없거나 호환되지 않으면 해당 위임을 보류하고 가능한 리더 작업을 계속한다. 자동 후보가 없으면 적합한 가용 후보를 이유와 함께 알린 뒤 선택할 수 있으나, 명시 제약을 완화하지 않는다. 거절된 실행이 부분 변경을 남겼는지 확인하기 전 새 worker를 보내지 않는다.

[세션 도구](session-tools.md)의 현재 schema와 custom agent 우선순위를 확인한다. `agents/openai.yaml`은 UI 메타데이터이지 모델 설정이 아니다. 모델명이 prompt에 있다는 사실이나 spawn 수락만으로 실행 모델을 확인했다고 하지 않는다.

리더의 모델·provider·로그인·`model_context_window`·`model_auto_compact_token_limit`을 변경하지 않는다. 특히 사용자의 큰 컨텍스트 설정을 일괄 축소하지 않는다. 워커의 상속 설정과 모델 호환성은 별도로 확인한다. 호환성을 확인할 수 없으면 미확인으로 남기고, 지원되지 않는 숫자/설정 키를 만들거나 호환성 해결을 위해 전역 설정을 고치지 않는다. 새 custom agent 파일 설치는 이 정책의 필수 단계가 아니다.

기본 운영 상한은 동시에 두 개의 내부 worker 요청이며, 실제 호스트 한도가 더 작으면 그것을 따른다. 사용자의 별도 한도가 우선한다. 이는 협력적 운영 규칙이지 전역 슬롯 설정이나 강제 잠금 구현이 아니다. 한 worktree의 writer는 여전히 하나다. 작업 격리가 불가능하면 다른 파일을 만지더라도 쓰기는 직렬화한다.

## 전달·실패·회수

목표·완료 조건, 실제 절대 경로, 필요한 입력/계약, 허용 변경·권한·기존 변경, 선택한 역할·모델·effort를 자기완결형으로 전달한다. 대화 전체를 복제하거나 중요한 계약을 단순히 토큰 절약을 위해 빼지 않는다. 필요한 맥락이 너무 커서 안전하게 줄일 수 없으면 리더가 유지한다.

워커는 새로운 설계 결정, 범위 확대, 근거 부족 또는 진전 없는 반복 실패를 리더에게 반환한다. 고정 횟수 재시도로 성공할 때까지 돌리지 않는다. 모델 교체는 새 근거와 지원되는 새 실행 경로가 있을 때만 한다. 실패한 워커와 새 워커가 동시에 같은 작업을 쓰지 않도록 실제 정지/상태를 확인한다.

리더는 반환 증거를 검사하고 필요한 제품 검증을 수행하되 완료된 구현·조사를 무조건 재수행하지 않는다. `desired`(정책), `submitted`(실제 요청), `observed`(실행 증거)를 구분한다. 관측할 수 없는 필드는 `unverified`이며 다른 클라이언트의 카탈로그나 전역 기본값으로 채우지 않는다. 요청값과 관측값이 다르면 정책 불일치로 보고하고 그 실행을 해당 모델의 성능 측정에 넣지 않는다.

## 경로 경계와 평가

Codex 내부 위임을 `gptplease`의 Chat/Work 상담이나 Unreal Agent runner로 자동 대체하지 않는다. 별도 sidebar 작업도 사용자의 새 작업 생성 요청이 필요하다. 현재 호출한 스킬의 trigger/권한을 다른 스킬에 전파하지 않는다.

효과는 Astra 단일 실행, Astra-only 위임, mixed-model 위임을 같은 시작 상태·완료 조건으로 비교한다. 메인과 모든 워커·재시도·통합까지 포함해 시간·사용량·품질을 기록하며 미관측 수치를 0으로 채우지 않는다. 저장소의 `docs/model-routing-review.md`와 `scripts/model_routing_eval.py`는 선택적 평가 자료다. 설치된 스킬만으로 저장소 평가 도구가 존재한다고 가정하지 않는다.

근거: [OpenAI Models](https://learn.chatgpt.com/docs/models), [OpenAI Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents), 확인 2026-09-25. 모델별 시작 조합은 공식 가이드의 출발점을 참고한 이 저장소의 정책이며, Astra 역할별 기존 effort는 사용자 운영 정책이다.
