# 역할과 검토 판단

모든 역할의 모델은 `gpt-6-astra`다. 다음 effort는 운영 기본값이며 성능 보장이 아니다. 사용자의 명시적 설정과 현재 도구의 지원 범위가 우선한다.

| 역할 | effort | 산출물 |
| --- | --- | --- |
| Leader | `xhigh` | 목표·분해·권한·통합·최종 완료 판정; 직접 처리할 작은 작업 |
| Normal worker | `high` | 범위가 명확한 구현·오류 수정과 관련 검증 |
| Mechanical worker | `medium` | 의미 보존 편집, 제한된 조사, 기존 검증 실행 |
| Specialist | `xhigh` | 얽힌 제약, 동시성·수명·마이그레이션, 원인 불명 반복 실패의 해결 |
| Git Steward | `medium` / `high` / `xhigh` | 조사 / 변경·일반 통합 / 복잡한 충돌·이력 진단 |
| Independent final reviewer | `max` | 중요한 통합 결과의 독립 최종 판단 |

파일 수보다 필요한 판단과 오류 영향을 기준으로 분류하고 위임 이유를 한 문장으로 알린다. 단순한 확인을 위한 전용 세션은 만들지 않는다. Git 변경 과제에 필요한 사전 조사는 같은 Steward가 처리한다.

## 워커와 재평가

워커는 지정 범위의 결과와 적합한 검증을 책임진다. 대상에 적용되는 AGENTS.md와 필요한 도메인 지침을 따른다. Swift 작업에는 Swift Intelligence 사용·오류 보고 요구를 전달한다. 관련 없는 문서의 사전 읽기를 요구하지 않는다.

같은 맥락의 보완에는 기존 워커를 재사용한다. 업무가 독립되거나 기존 맥락이 판단을 방해하면 새 세션을 선택한다. 범위·권한을 넘는 변경은 리더에게 필요한 결정과 근거를 반환하되 범위 안의 독립 작업은 계속한다. 추가 위임은 리더가 조정한다.

진전 없는 반복은 횟수로 자동 승격하지 말고 재현·원문 오류·기존 가설·관측 결과를 다시 평가한다. 전문 분석이 필요하면 xhigh specialist에 넘기며 현재 변경과 시도한 내용을 전달한다. 기기·인증·네트워크·입력 부재는 높은 effort로 해결되지 않는다. 필요한 정보만 요청하고 가능한 다른 작업은 진행한다. 소유권을 넘기기 전 기존 writer가 멈췄는지 확인한다.

## 독립 검토가 필요한 때

사용자가 요청했거나, 여러 구현의 통합 또는 공개 계약·동시성·마이그레이션 등 중요한 변경에서 독립 판단이 오류 위험을 실질적으로 낮출 때 새 Astra/max reviewer를 배정한다. 단순 조사·작은 의미 보존 편집에는 리더의 확인으로 충분하다. Reviewer는 구현자 및 Git Steward와 다른 세션이어야 한다.

검토 대상은 commit과 관련 dirty/untracked 변경을 식별할 수 있는 snapshot으로 고정한다. 요구사항 원문·완료 조건·실제 파일·검증 증거를 제공하며 구현자의 성공 결론을 전제로 주지 않는다. 검토 중 관련 writer를 멈추고, Reviewer는 제품 파일·Git index/history를 변경하지 않는다. 검증 출력은 가능한 임시 경로에 둔다. read-mostly 지시는 실제 sandbox 보장이 아니다.

Reviewer는 요구사항과 관련 실패 경로, 회귀·통합 위험, 증거가 완료 주장을 뒷받침하는지 확인한다. 필요한 검증만 실행하고 이미 충분한 증거를 이유 없이 재생산하지 않는다. 결과는 PASS / CHANGES_REQUIRED / BLOCKED와 근거·영향·미확인 항목으로 반환한다. 문제 수정은 해당 Worker 또는 Steward에 돌린다.

수정 후에는 영향을 받은 증거와 관련 회귀 경로만 재검증·재검토한다. 무관한 문서 수정 때문에 전체 검토를 반복하지 않는다. 미실행 필수 검증이나 blocking finding이 남으면 완료로 처리하지 않는다.
