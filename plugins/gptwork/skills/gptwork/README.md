# gptwork

사용자의 요청을 독립적인 지시문으로 정리하고, **GPT-6 Astra와 난이도별 사고 수준을 설정·검증해 Work에 제출하고, 완료 응답을 호출한 세션으로 가져와 처리하는 스킬**입니다. 별도로 “모델도 설정해 달라”고 말할 필요가 없습니다.

```text
$gptwork gptwork 스킬을 Work에서 검토해주세요.
```

1. 요청의 목표·맥락·산출물·완료 기준을 정리합니다.
2. 모델은 GPT-6 Astra로 선택하고, 질문의 난이도에 따라 사고 수준을 정해 이유를 짧게 알립니다. 명시한 설정과 비용·시간 제한을 우선합니다.
3. 실제 Work 입력창에서 모델을 선택하고, 그 뒤 사고 수준을 선택합니다.
4. 입력창에 표시된 두 값을 확인한 다음 같은 입력창에서 요청을 한 번 제출합니다.
5. 같은 호출 세션에서 응답 완료를 기다린 뒤, 요청한 차례의 최종 응답 전체를 가져옵니다.
6. 호출 세션이 응답을 검토하고 원래 요청에 따라 답변·계획·수정·검증을 이어갑니다. 작업 링크만 보고 끝내지 않습니다.

모델은 **Astra가 기본**이며 쉬운 질문이라고 다른 모델로 낮추지 않습니다. 단순 정리는 Light, 일반 설명·비교는 Medium, 중요한 검토·설계는 High, 얽힌 제약·모순은 Extra High, 영향이 큰 핵심 최종 판단에는 Max를 선택적으로 사용합니다. 실제 Astra 선택기에 있는 수준만 사용하며, 사용자가 명시한 다른 모델·수준은 우선합니다. Astra가 없으면 임의 대체 없이 전송을 보류합니다.

프로젝트 지정이 없으면 프로젝트 없는 Work를 사용합니다. 기존 작업의 후속 요청도 해당 입력창에서 설정을 확인한 뒤 전달하고 해당 응답을 기다립니다. 로컬 자료와 이전 대화는 자동 첨부되지 않습니다. 대기 중에는 진행 상황을 알리고 취소·시간 제한을 따릅니다. 명시적으로 “생성만 하고 기다리지 마세요”라고 요청한 경우에만 수집을 생략합니다.

응답은 Work의 제안으로 취급하고 현재 파일과 요청에 대조합니다. 검토만 요청했다면 발견 사항을 보고하고, 수정까지 요청했다면 이미 허용된 변경과 테스트를 호출 세션에서 진행합니다. 응답이 잘렸거나 산출물에 접근할 수 없으면 미수집 범위를 알립니다. [응답 대기·회수·처리](references/response-return.md)가 상세 기준입니다.

## 파일 첨부

파일 전달 요청은 지원되는 브라우저 업로드 기능으로 해당 파일을 실제 첨부합니다. 업로드 완료와 모델·사고 수준을 같은 입력창에서 확인한 뒤 한 번 전송하고, 전송 후에도 해당 사용자 메시지의 첨부를 확인합니다. 경로만 보내거나 파일 내용을 프롬프트에 붙여 넣은 것을 실제 파일 첨부 성공으로 보고하지 않습니다. 지원 API는 실행 시 확인하며, 첨부 실패 시 파일을 제외하고 전송하지 않습니다. [파일 첨부 절차와 검증 범위](references/file-attachments.md)를 참고하세요.

2026-09-07에는 이전 대화를 복제하지 않은 새 세션에서 설치 스킬의 자동 노출, Astra Light 설정, JSON 실제 첨부, 완료 응답 회수·원문 대조를 확인했습니다. 회수된 첨부 파일도 원본과 바이트 단위로 일치했습니다. 새 작업의 Light 응답과 동일 작업의 Medium 후속 응답도 검증했습니다. 이는 관측한 UI 설정과 단일 JSON 사례의 증거이며 서버 내부 모델 메타데이터나 다른 파일 형식 전체를 검증한 것은 아닙니다.

## 설정을 건너뛰지 않는 실행

현재 네이티브 `create_thread`의 Work 대상은 모델·사고 수준을 지정하지 못하므로 **기본 경로는 브라우저 Work UI**입니다. UI에서 설정해 놓고 별도로 네이티브 생성을 호출하면 같은 설정이 적용된다고 가정할 수 없습니다. 도구·로그인·설정 확인이 막히면 프롬프트를 보존하고 전송 전에 중단하며, 기본 모델로 생성한 뒤 추천만 보고하지 않습니다.

사용자가 “현재 설정 그대로” 또는 “추천만”이라고 명시한 경우에는 해당 선택을 따릅니다. 이미 실행 중인 작업의 입력창 설정을 변경해도 이전 응답에 소급 적용됐다고 보고하지 않으며, 중단·재전송하지 않습니다. 상세 절차는 [모델 선택](references/model-selection.md)에 있습니다.

스킬의 로컬 설명·편집과 프롬프트 초안 요청은 Work 작업을 만들지 않습니다. 반면 “이 스킬을 Work에서 검토”는 실제 Work 실행 요청입니다. 기존 Desktop gptpro Runner·Launcher·Node/Python 설정은 필요하지 않으며, 지원되는 브라우저 제어와 Work 로그인이 필요합니다.

## 설치

저장소 marketplace에 이 변경이 공개된 뒤 `gptwork@codex-skills` Plugin을 선택 설치할 수 있습니다. standalone 설치는 `gptwork/` 스킬을 선택합니다. 기존 `scripts/manage_skills.py`는 Desktop `gptpro` 전용이므로 이 스킬의 설치에 사용하지 않습니다. 설치는 실행 중인 작업의 도구 가용성을 바꾸지 않으므로 새 작업에서 로드 여부를 확인합니다.

운영 지침은 [SKILL.md](SKILL.md), 전달 예시와 실패 처리는 [task handoff](references/task-handoff.md)를 참고하세요. 실제 Work 생성은 사용자의 생성 요청이 있을 때만 실행합니다.
