# Local AI Studio setup

Read when LocalAIHub, its `ai` CLI, or the model group needed for a requested Local AI Studio or on-device model task is absent. Installing a missing prerequisite is in scope for that request; a generic media request does not authorize a large local download. Install only the needed group. Keep source checkout, model storage, and generated output distinct.

## Find what is already present

Check the user's source/app/CLI path first, then the configured `AIHUB_ROOT`, `~/Library/Application Support/Local AI Studio/config.json`, `command -v ai`, and a plausible existing source checkout. Confirm any `ai` candidate with `--help` and `status`; a command named `ai` may be unrelated. Do not overwrite an existing checkout, app, CLI, model root, or generated files. If a configured external volume is unmounted, restore or ask for that volume instead of silently moving its data to the internal disk.

The public source is [oozoofrog/LocalAIHub](https://github.com/oozoofrog/LocalAIHub). Prefer an existing user-selected checkout; otherwise clone into a new, user-writable source directory, such as `~/LocalAIHub` when unused. Inspect its Git status, origin, README, installer help, and available CLI commands. A clean fresh clone can be built as documented; do not pull over local changes. The published `main` may lag another local checkout, so check actual support for the requested modality rather than assuming the examples in this skill exist in every revision.

## Prepare one model group

- Check Apple Silicon and the source revision's macOS requirement (currently macOS 14+), Xcode Command Line Tools, `git`, `curl`, network access, and CMake when installing image generation. Inspect the current `README.md`, `THIRD_PARTY_NOTICES.md`, and `Sources/AIHubCore/Installer/install.sh` before running its network and build steps. The installer can fetch `uv`, Python, runtime sources, and model weights.
- Map the requested work to the installer group: image generation/editing → `image`; TTS/transcription → `audio`; video → `video`; music → `music`; English→Korean translation → `translation` only if that revision supports it. Current source estimates are roughly 13, 12, 16, 10, and 2 GB respectively, plus runtime packages and caches. Recheck current estimates, available space, destination, and active model/install jobs before downloading. Tell the user the selected root, group, and approximate download size before starting; proceed when the local task already authorizes setup.
- Honor a user-chosen model root. With no prior choice, use the selected revision's documented fallback only after checking free space. Keep `AIHUB_ROOT` scoped to setup and use commands; do not edit shell profiles or install a global `ai` command unless requested. Check the selected root and source checkout for existing data before writing.
- For `image`, read the [current Qwen license](https://huggingface.co/Qwen/Qwen-Image-2.1/blob/main/LICENSE). The installer requires `--accept-qwen-research-license`; add that flag only after the user explicitly accepts the applicable terms. A request to generate an image or install LocalAIHub alone is not acceptance. If the user has a separate commercial license, verify the applicable path before selecting this model.

Build the app with the source revision's documented `./script/build_and_run.sh build-only`, which creates `dist/LocalAIStudio.app` without launching it. Its bundled `Contents/Resources/ai` avoids a global CLI install. For a CLI setup, inspect the current installer `--help`, run its `--dry-run` for the chosen root/group when supported, then run `/bin/bash Sources/AIHubCore/Installer/install.sh --root "$MODEL_ROOT" --models "$GROUP"` from that checkout. The image group enforces Qwen acceptance even for `--dry-run`; do not pass the acceptance flag just to preview. Add it only after explicit acceptance. Use verified absolute paths and safely quoted arguments. The app's **Model Setup** is an alternative when the user wants the native installation UI. It saves the selected root and places a matching `ai` in that root's `bin` directory.

## Confirm setup and continue

Record the source revision, app/CLI path, root, selected group, installer exit status, and any failures. Set `LOCAL_AI_CLI` and `MODEL_ROOT` to verified absolute paths, then run `AIHUB_ROOT="$MODEL_ROOT" "$LOCAL_AI_CLI" --help`, `status`, and `models` with the same root; confirm the selected group is `READY`. A bundled app, a successful build, or `READY` does not prove inference. If the requested command is present, continue with [the task workflow](cli-workflows.md) and verify its actual output. If the request was only to install, finish after readiness checks and state that inference was not run.

On failure, retain partial downloads and existing data for a bounded retry after diagnosing the cause. Do not delete weights, pull across a dirty checkout, or rerun a large download blindly. If the public checkout lacks the requested command, use a user-provided newer source/revision or report the missing capability; do not quietly substitute another model or claim that an unpublished local change is available remotely.
