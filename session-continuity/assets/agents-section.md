## Codex Session Continuity

상당한 작업은 `.codex/work/<task-id>.md`에 현재 복구 지점을 유지한다. 이 파일은 임시 상태이며, 사용자 지시·적용되는 저장소 규칙·확정된 요구사항을 대체하거나 새로운 권한을 부여하지 않는다.

### 세션 시작

1. 적용되는 `AGENTS.md`와 override 규칙을 읽는다.
2. 요청한 task-id의 state를 읽는다. `_template.md`와 `archive/`는 활성 작업이 아니다. 작업이 여러 개이고 요청만으로 식별할 수 없으면 임의로 고르지 않는다.
3. 실제 저장소/worktree 경로, branch, HEAD, `git status`, staged/unstaged diff와 관련 untracked 파일을 확인한다.
4. state와 실제 상태를 대조한다. 구현 사실은 현재 파일·Git·실행 증거로 확인하고, 요구사항과 규칙은 그대로 적용한다. 불일치는 원인을 확인한 뒤 state를 정정한다.
5. `Relevant Files`의 코드·테스트·문서부터 읽고 `Exact Next Action`의 첫 행동을 수행한다. 이전 대화는 빠진 근거가 있을 때만 참조한다.

### 작업 중과 세션 경계

결정 확정, phase 완료, 검증 결과나 다음 행동 변경 시 state를 갱신한다. 긴 대화 로그를 복사하지 않는다. 새 증거가 없는 한 완료된 조사나 폐기한 접근을 반복하지 않는다.

조사 결론, 일관된 구현 단위, 관련 검증 완료 등 의미 있는 경계에서 checkpoint를 준비한다. 토큰 잔량을 추측해 압축 시점을 보장하지 않는다. 사용자가 계속 진행하도록 맡긴 작업은 가능한 범위에서 계속하며 phase 완료만으로 전체 완료를 선언하지 않는다. 세션 교체 요청이 있으면 가까운 안정 지점에서 handoff를 남긴다.

### 종료 전 checkpoint

- 가능한 안정 지점까지 진행한 뒤 현재 Git 상태와 변경 내용을 확인한다.
- 필요한 관련 검증을 실행하되, 입력 변경·새 실패·구체적 우려가 없으면 통과한 검증을 반복하지 않는다.
- 완료/부분 완료/실패/차단/미검증을 구분한다. 실행한 검증만 명령, 범위, 시각, 대상 HEAD와 당시 미커밋 변경, 실제 결과로 기록한다. 미실행은 `NOT RUN`, 중단은 `INCOMPLETE`로 남긴다. 자동화·Simulator·실기기·사람·설치·릴리스 증거를 구분한다.
- state의 시각, 저장소/worktree, branch, HEAD, 변경 목적, 결정, 미해결 질문, 관련 파일, 정확한 다음 행동을 갱신한다. 관측 사실과 가설을 구분한다.
- dirty 상태는 허용한다. staged/unstaged/untracked 변경별 목적과 완료도를 적고, 사용자나 다른 작업의 변경은 보존한다. checkpoint를 위해 commit, stash, reset, clean, push를 임의로 수행하지 않는다.
- 갑자기 종료해야 하면 현재 상태·미검증·다음 행동부터 저장하고 불안정성을 명시한다. 저장한 파일을 다시 읽어 이전 대화 없이 재개할 수 있는지 확인한다.

### 작업 완료

전체 완료 조건과 필요한 검증을 확인하고, 오래 유지할 결정·계약·운영 정보는 적절한 코드/테스트/프로젝트 문서/ADR에 반영한다. 승격 위치를 state에 남긴 뒤 임시 state 삭제 또는 `archive/` 보관을 안내한다. 정리까지 맡겨졌다면 보관을 기본으로 하고 명시적으로 요청한 경우 삭제한다. 다른 작업 state는 건드리지 않는다.

`.codex/work/`는 기본적으로 Git 제외를 권장하지만 프로젝트 선택을 따른다. ignore된 state와 미커밋 변경은 다른 clone/worktree로 자동 전달되지 않으므로 재개할 위치에서 실제로 접근 가능한지 확인한다.
