# 기존 테스트 개선: 연구와 적용 판단

조사일: 2026-09-13. 벡의 직접 작성 자료를 품질 기준의 중심으로 두고, 연구진의 논문과 기업의 직접 보고를 실행 절차의 참고로 삼았다. 아래 수치는 각 연구의 조건에서 나온 결과이며 이 스킬이나 모든 언어에서의 성능을 뜻하지 않는다.

## 그대로 도입하지 않은 부분

- TestGen-LLM은 제품 결함과 잘못된 기대값을 자동 판별하기 어려워 처음부터 실패하는 후보를 버리고, 커버리지를 늘리지 않는 후보도 버린다. 이 스킬은 그 자동화 제약을 그대로 따르지 않는다. 실패는 분류할 대상이며, 검증문 강화·속도·진단력 개선은 커버리지 증가 없이도 가치가 있다.
- TestGen-LLM의 고정 5회 실행, TestForge의 20개 이상 테스트 요청과 고정 반복 한도는 연구 도구의 설정이다. 벡의 원칙이나 일반적인 스킬의 필수 조건으로 옮기지 않는다.
- TestForge의 결과는 테스트 생성 벤치마크의 결과다. 제품 저장소나 모델이 달라졌을 때 동일한 개선을 보장하지 않으며, 실행 오류의 실제 출력만 보고 기대값을 바꾸는 방식을 허용하지 않는다.
- [TestGenEval](https://github.com/facebookresearch/testgeneval)은 기존 테스트 완성과 새 테스트 생성 과제를 구분하고 실행·커버리지·변이 지표를 구분한다. 여기서는 평가 구분을 참고하며 대규모 벤치마크나 외부 서비스를 설치하지 않는다.

## 스킬 설계

새 동작의 TDD와 기존 테스트 개선은 진입 경로를 구분한다. 기존 테스트 개선에서는 현재 보장·실행 상태 확인 → 문제와 기대값 근거 파악 → 한 가지 개선 → 효과와 보장 보존 확인으로 진행한다. 점검 요청과 변경 요청도 구분한다. 이것은 위 자료를 종합한 작성자의 적용 설계이며 벡이 제시한 별도의 공식 알고리즘이 아니다.

예상 결과가 알려진 잘못된 동작을 잡는지, 정상적인 구조 변경에도 통과하는지를 따로 살피는 것이 핵심이다. 이를 확인하기 위해 작성자가 만든 두 작은 격리 예제를 실행했다. 한 예제에서는 같은 제품 코드 줄을 실행하는 두 테스트 중 구체적인 결과를 검증한 테스트만 필터 제거 결함을 잡았다. 다른 예제에서는 내부 저장 표현을 바꿨을 때 내부 필드를 확인하는 테스트는 실패하고 공개 동작 테스트는 통과했다. 이 예제들은 판단 기준을 설명하며, 스킬을 읽은 에이전트의 수행 능력이나 일반적인 결함 발견률을 검증한 실험은 아니다.

스킬의 실제 행동 평가는 향후 구체적인 저장소에서 다음 상황을 구분해 확인해야 한다: 점검만 요청한 작업의 변경 없음, 테스트 개선 중 제품 결함 발견 시 기대값 근거 보존, 높은 커버리지·약한 검증 개선, 동작 보존 구조 변경에 대한 내성, 실행 순서 의존성 해소. 문구나 제목의 일치 검사는 이러한 행동 평가를 대체하지 않는다.
